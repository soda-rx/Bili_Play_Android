# 开发与验证

安卓工程独立维护，Windows项目只读参考，不运行Windows构建/清理工具。

## 结构

- core：API/协议、音乐频道及指定UP轮换、字幕/队列策略、下载/MP3编码；test只用合成数据。
- app/data：加密凭据、账号隔离、SQLite记录及设置。
- app/playback、app/download：Media3服务与WorkManager任务。
- app/update：独立 GitHub 更新客户端、APK 完整性与身份/签名校验；安装确认由用户触发。
- app/comment：图片在内存中限尺寸解码、压缩和移除原始元数据，不缓存所选照片到文件。
- app/ui：入口协调器、AppState、首页/播放器/收藏搜索/社交/下载/账号/设置页面及通用组件/弹窗；theme保留完整12组主题。
- tools：隔离工具链、构建、清理与隐私检查。Windows工程只读参考，不参与安卓构建。

## 构建

使用 PowerShell 7 或更高版本执行项目脚本。准备工程外的JDK 21、Android SDK API 37、Build Tools 36.0.0和Gradle 9.6.0，可使用 tools/Setup-Toolchain.ps1，生成的toolchain.json与缓存/签名均在工程外。

```powershell
./tools/Build-Android.ps1 -ToolchainFile <工程外的toolchain.json> -VerifyRelease
```

运行离线回归、开发Debug/R8 Release及两种Lint，验证包身份、显示名和隐私，最后自动清理生成目录。交付时加 -Deliver，只在桌面根目录输出 Bili_Play_Android_<版本>.apk 单文件，不创建文件夹或附带文件；协议/许可保留在应用内，不自动安装。

开发构建必须显式 -PDevelopmentBuild=true，身份 io.github.sodarx.biliplay.development；正式构建必须显式 false，签名密钥在工程外。两种构建均显示Bili Play，各账号凭据/记录/下载互相隔离。禁止日用数据进入源码、测试或安装包，不输出敏感值。


## 发布

测试完成后清理生成物并检查源码/暂存内容/APK隐私。安装包只放桌面根目录：`Bili_Play_Android_<版本>.apk`，不附带文件。不自动安装，不清理用户数据。

Git Tag不带v（例如`0.2.33`）；附注Tag说明`Bili Play Android v0.2.33`。推送代码与Tag不自动创建GitHub Release。MIT及第三方授权必须保留，见根目录LICENSE、third_party及应用内协议/许可。

详细发布规则、版本递增、Release 标题、预发布和附件校验见 [RELEASING.md](../RELEASING.md)。Build-Android.ps1 用于 development 隔离验收；正式交付使用 Build-Production.ps1，显式构建 Production Release 并用工程外固定正式密钥签名。

覆盖升级还必须匹配既有签名。已从 0.2.33 安装包核实其身份为 io.github.sodarx.biliplay.development，公开证书 SHA-256 为 deee5396960058b640cb87b89ab038dc81c97551595963ba7bb856a2cdb2b889，保存在 release-policy.json。-Deliver 在构建前核对密钥的公开证书，签名后再次核对 APK；不匹配或缺少原始密钥时停止，不自动生成新密钥交付。可用 -DevelopmentKeystore 指定工程外的既有开发密钥位置，私钥不得复制进工程或分发。普通隔离测试构建的签名有效，不代表能够覆盖已安装版本。

此前生成的 0.3.1/0.4.0 验收包使用新开发密钥，与 0.2.33 的证书不匹配；这些包不能作为其覆盖升级包。不能从旧 APK 的公开证书恢复私钥，也不改写已发布附件或删除用户安装。

1.0.0 / 39 的 260 项核心离线回归、10 项发布工具回归、Development Debug/R8 Release 及两种 Lint、Production R8 Release/Lint 均通过。最终 APK 已核对正式身份、非调试/非测试/禁备份标记、固定证书、ZIP 对齐及隐私；已交付桌面单 APK 并清理工作区生成物。签名目录合并后，核对文件一致、DPAPI 解密及恢复密码匹配，并使用迁移后的私钥签署合成数据及验签，固定证书未变。未安装、真实登录、发表评论、提交、打标签或发布 Release。

## 0.3.1 验证记录与边界

250 项合成离线回归、Development Debug/R8 Release、两种 Lint 和源码/APK 隐私检查通过。未运行真实账号或 OEM/平板真机验收，也没有自动安装 APK、提交源码、打标签或发布 Release。

收藏夹与 UP 空间搜索走带关键词的分页请求，播放列表按原始出现项索引筛选。批量下载只对已选结果创建任务，跳过已完成和进行中的下载。旧式多段音源使用单时间轴播放，单独切换故障分段的备用地址；这种旧格式目前不做分段合并下载，明确拒绝以避免只保存第一段。

更新 APK 的 SHA-256 在 GitHub 提供 digest 时核对；无论是否提供摘要，都核对安装包身份、递增 versionCode、公开版本和签名。正式/开发身份及签名不匹配时拒绝交给安装界面。未知来源授权和安装确认均由用户操作。

## 0.4.0 评论图片

评论和回复解析 content.pictures，缩略图支持点击全屏查看、缩放及切换。通过系统照片选择器选择最多九张；不添加整个相册的读取权限，低版本使用系统选择器回退并在应用内再次限制数量。待发送 URI 和上传内容只保留在当前会话内，所选照片预览禁用磁盘和内存图片缓存。

点击发送后才验证当前账号并处理图片，输入限 20 MB/8000 万像素，输出最长边 2048 像素且不超过 4 MB。重新编码为 PNG/JPEG 静态图片，上传使用统一文件名，不携带原文件名或 EXIF 位置等元数据。接着上传图片并把返回元数据交给评论接口；图片评论没有填写文字时使用“[图片]”占位。回复页默认保留所在根评论的目标。

260 项合成离线回归、Development Debug/R8 Release、两种 Lint、签名与源码/APK 隐私校验通过。新增协议测试覆盖图床来源、上传参数、图片评论/回复、数量及尺寸限制、无凭据拒绝和禁止重定向。未使用真实账号上传照片或发表评论，实际账号权限、平台风控及真机照片选择/图片查看仍需用户验收。

接口参考为公开的[带图评论实现](https://gist.github.com/yige233/09803324a5bac731d7de71d984406952)，属于社区协议参考，并非平台承诺的稳定开放接口。系统选择器参考 [Android Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker)。
